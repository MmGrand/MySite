## О проекте

Проект реализован мной для личного использования и тренировки в разработке. В будущем можно изменить стили и выложить его на хостинг как сайт-портфолио. 

Публичная часть — отдельное Vue SPA, использующее Laravel API на том же домене. Проект включает авторизацию пользователей и мини-профиль. Пользователи могут оставлять комментарии под постами. На главной странице отображаются проекты и посты; их можно фильтровать по тегам и категориям. Также есть страницы «Контакты» и «Обо мне».

## Используемые технологии

- **PHP:** 8.2 или новее.
- **Laravel:** Фреймворк для разработки веб-приложений на PHP.
- **MySQL:** Система управления базами данных для хранения информации.
- **Vue 3 и Vue Router:** публичный интерфейс и клиентская маршрутизация.
- **Vite:** сборка и сервер разработки SPA.
- **Laravel Sanctum:** сессионная авторизация SPA и защита CSRF.
- **npm:** Менеджер пакетов для JavaScript.
- **JavaScript:** язык клиентского приложения.

## Установка

### Запуск через Docker

Для запуска нужны PHP 8.2+ и Composer (для установки PHP-зависимостей), Node.js 18+ и npm, а также Docker Desktop.

1. Клонируйте репозиторий и перейдите в его папку:
   ```sh
   git clone https://github.com/MmGrand/MySite.git
   cd MySite
   ```
2. Создайте `.env`, только если его ещё нет, и установите зависимости:
   ```sh
   cp .env.example .env
   composer install
   npm ci --prefix frontend
   ```
   В PowerShell вместо `cp` можно выполнить `Copy-Item .env.example .env`.
3. Сгенерируйте ключ приложения:
    ```sh
    php artisan key:generate
    ```
4. Для Docker-профиля в `.env` установите значения БД:
   ```dotenv
   DB_CONNECTION=mysql
   DB_HOST=mysql
   DB_PORT=3306
   DB_DATABASE=laravel
   DB_USERNAME=sail
   DB_PASSWORD=password
   ```
   Адрес `mysql` используется между контейнерами; `127.0.0.1` внутри контейнера Laravel указывает на сам Laravel, а не на MySQL. Пароль здесь приведён для локальной разработки — при необходимости замените его.

   Если том MySQL уже создан, изменение `DB_USERNAME` или `DB_PASSWORD` в `.env` не меняет существующих пользователей и пароли в базе. Используйте действующие учётные данные или измените их в MySQL; удаление тома уничтожит его данные.
5. Соберите фронтенд и запустите контейнеры:
   ```sh
   npm run build --prefix frontend
   docker compose up -d --build
   docker compose exec laravel.test php artisan migrate --seed
   docker compose exec laravel.test php artisan storage:link
   ```
6. Откройте `http://localhost`. Если порт 80 занят, задайте `APP_PORT=8000` в `.env` и откройте `http://localhost:8000`.

Для разработки с Vite используйте `npm run dev --prefix frontend` вместо сборки и оставьте Laravel запущенным. Открывайте сайт по адресу Laravel, а не Vite: API и cookies работают на том же origin. Если запускаете Laravel вне Docker, укажите в `.env` адрес и реквизиты локальной MySQL, затем выполните `php artisan migrate --seed`, `php artisan storage:link` и `php artisan serve`.

### SPA, авторизация и почта

- Исходники SPA и собственный lockfile находятся в `frontend`; production-сборка записывается в `public/spa`. Laravel отдаёт HTML-оболочку для известных адресов SPA и отдельные `/api/*` и `/sanctum/*`. Настройте веб-сервер так, чтобы запросы к этим маршрутам доходили до `public/index.php`, а существующие файлы отдавались напрямую.
- Установите `APP_URL` на реальный адрес сайта и при необходимости добавьте его хост и порт в `SANCTUM_STATEFUL_DOMAINS`. Сессия и CSRF-cookie должны использовать тот же домен, что и сайт; отдельный домен API в этой конфигурации не поддерживается.
- Восстановление пароля работает только через одноразовую ссылку из письма. Настройте `MAIL_MAILER`, `MAIL_HOST`, `MAIL_PORT`, учётные данные и адрес отправителя (`MAIL_FROM_ADDRESS`, `MAIL_FROM_NAME`) в `.env`. Без работающей почты пользователи не получат ссылку; `MAIL_MAILER=log` пригоден только для локальной разработки.
- SPA без SSR: динамический контент зависит от JavaScript и может индексироваться поисковиками иначе, чем прежние Blade-страницы.
